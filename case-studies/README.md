# Case Studies

These case studies explain real-world security incidents from a defensive Application Security and security engineering perspective. The focus is on what the incident teaches about visibility, ownership, controls, and business impact.

## Featured Studies

| Case Study | Primary Theme | AppSec Lesson |
| --- | --- | --- |
| [Log4Shell](log4shell.md) | vulnerable open source component | Dependency inventory and rapid exposure-based remediation are essential. |
| [SolarWinds](solarwinds.md) | software supply chain compromise | Build systems, vendor trust, and software integrity need security controls. |
| [MOVEit](moveit.md) | third-party managed file transfer exposure | Internet-facing data transfer systems require strong monitoring, patching, and incident readiness. |
| [Application security assessment sample](appsec-assessment-sample.md) | application risk assessment | Findings should connect risk, business impact, remediation ownership, and evidence. |

## Review Lens

Each case study should answer:

- what risk existed
- why the business impact mattered
- how affected systems could be identified
- which controls reduce recurrence
- what evidence a security team would need during response

The goal is to demonstrate practical judgement, not to retell incidents as offensive narratives.
